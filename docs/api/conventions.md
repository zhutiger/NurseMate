# API 通用约定

## 1. 基础约定

- 协议：当前云端测试环境按项目决定暂用 HTTP；正式环境上线前必须切换为 HTTPS。
- 基础路径：`/api/v1`。
- 数据格式：请求和响应使用 UTF-8 JSON；文件上传除外。
- 字段命名：JSON 使用 `camelCase`，数据库使用 `snake_case`。
- 时间格式：RFC 3339 UTC 时间，例如 `2026-11-19T06:30:00.000Z`。
- 标识符：对外统一使用 UUID 字符串，不暴露数据库自增序号。
- 服务端时间：发布时间、查看时间、确认时间、提交时间、审核时间和审计时间均由服务端生成。

## 2. 认证与会话

- 除激活、登录和刷新令牌外，接口使用 `Authorization: Bearer <accessToken>`。
- 小程序、H5 和管理网页使用同一内部账号体系；`clientPlatform` 仅描述会话来源。
- 访问令牌短时有效，刷新令牌按设备会话保存并支持轮换。
- 退出、账号停用、密码重置和管理员强制下线会使相关刷新会话失效。
- 微信身份关联失败不影响账号密码登录，不把 `openid` 当作业务用户 ID。

## 3. 标准响应

单对象成功响应：

```json
{
  "data": {},
  "requestId": "01J..."
}
```

分页成功响应：

```json
{
  "data": [],
  "page": {
    "page": 1,
    "pageSize": 20,
    "total": 42,
    "totalPages": 3
  },
  "requestId": "01J..."
}
```

失败响应：

```json
{
  "error": {
    "code": "TASK_STATE_CONFLICT",
    "message": "任务当前状态不允许该操作",
    "details": {
      "currentStatus": "APPROVED"
    }
  },
  "requestId": "01J..."
}
```

## 4. 分页、筛选和排序

- 页码从 1 开始，默认 `page=1&pageSize=20`，`pageSize` 最大 100。
- 时间范围使用 `from` 和 `to`，均为包含边界的 RFC 3339 时间。
- 多状态筛选使用重复查询参数或逗号分隔值，具体以 OpenAPI 为准。
- 默认按业务发生时间倒序；客户端不能传任意数据库字段作为排序字段。

## 5. 幂等与并发

- 发布、确认、简单完成、提交、审核、退回、催办和导出创建请求必须携带 `Idempotency-Key`。
- 幂等键由客户端生成 UUID；登录后的接口按用户、方法、路径和幂等键确定请求，激活与重置接口按工号、方法、路径和幂等键确定请求。
- 同键同请求体返回首次业务结果；同键不同请求体返回 `IDEMPOTENCY_KEY_REUSED`。
- 状态更新使用数据库事务和条件更新。并发冲突返回 HTTP 409，并在 `details.currentStatus` 中返回当前服务端状态。
- 客户端收到 409 后刷新详情，不在本地强制覆盖状态。

## 6. 权限与数据范围

服务端依次校验：令牌、账号状态、科室归属、角色或权限、数据范围、业务状态。前端隐藏按钮只用于体验，不构成授权。

- 普通护士只能访问本人接收的通知、本人任务和本人记录。
- 协管员必须同时满足具体权限代码和可管理的数据范围。
- 护士长只能管理本人所在科室。
- 资源不存在与无权访问在可能泄露他人数据时统一返回 404。

## 7. 文件流程

1. 调用文件预签名接口取得上传凭据。
2. 客户端直接上传文件存储。
3. 调用完成接口，服务端核对对象、大小、摘要和类型。
4. 业务提交只引用状态为 `READY` 的 `fileId`。

文件不得包含患者病历、身份证、具体病情或诊疗影像。服务端必须限制扩展名、MIME、单文件大小、数量，并保留拦截结果。

## 8. 审计

发布、版本变更、确认、提交、审核、退回、催办、导出、人员和权限变更必须写审计日志。失败的高风险管理操作也应记录结果和原因。日志不得保存密码、访问令牌、刷新令牌、激活码明文或微信密钥。
