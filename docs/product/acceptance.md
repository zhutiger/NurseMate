# 护知音 HZY V1.0 验收基线

## 1. 验收数据

建立以下独立测试数据：

- 1 名护士长。
- 1 名具有发布、统计、催办和审核权限的协管员。
- 1 名没有任何管理权限的协管员。
- 8 名普通护士，分为两个护理分组。
- 1 名待激活人员和 1 名已停用人员。

## 2. 身份与权限验收

| 用例 | 预期结果 |
| --- | --- |
| 在小程序使用有效激活码激活 | 账号激活、密码设置、微信身份关联、审计日志生成 |
| 在 H5 使用有效激活码激活 | 账号激活并设置密码，不依赖微信身份 |
| 小程序与 H5 使用同一账号密码登录 | 两端关联同一个内部用户 ID |
| 重复提交激活请求 | 返回同一绑定结果，不生成重复身份 |
| 使用过期或已使用激活码 | 拒绝绑定，不泄露账号详情 |
| 停用已登录用户 | 旧会话失效，后续请求被拒绝 |
| 无权限协管员访问管理接口 | 返回无权限，不产生业务写入 |
| 普通护士访问他人任务 | 返回无权访问 |
| 停用最后一名护士长 | 系统拒绝操作 |
| 编辑工号为已有工号 | 返回冲突，原账号和历史记录不变 |
| 停用后查看人员列表 | 展示服务端停用时间及原输入原因，按账号状态筛选结果正确 |
| 重新启用已停用账号 | 转为待激活，旧会话和旧密码不能使用，重新激活后恢复登录并保留停用记录 |
| 修改协管员权限 | 保存后权限查询、接口授权和审计记录同步变化 |

## 3. 通知闭环验收

1. 护士长向 10 人发布重要通知。
2. 系统生成固定的 10 人接收名单。
3. 6 人查看并确认，1 人仅查看，3 人未查看。
4. 管理端准确显示 6 人已确认、4 人未确认，并可追溯人员明细。
5. 对 4 人发起催办，生成 4 条提醒记录，确认状态保持不变。
6. 将当前时间推进至截止后，显示 1 人逾期未确认、3 人逾期未查看。
7. 修改正文生成新版本并要求重新确认，原确认记录仍可查询。
8. 一名护士重复点击确认，只产生一次当前版本确认记录。
9. 排除一名误选人员后，有效接收人数和统计口径同步更新，历史记录保留。

## 4. 任务闭环验收

1. 发布一个简单完成任务，负责人点击完成后记录服务端时间。
2. 重复完成请求不产生重复完成记录。
3. 发布一个需要审核的任务并指定 5 名负责人。
4. 一名负责人提交文字与附件，状态变为已提交。
5. 管理员退回并填写意见，状态变为退回补充。
6. 负责人重新提交，形成第 2 次提交，第一次提交保持不变。
7. 管理员审核通过，状态变为已通过。
8. 两名管理员并发审核同一提交时只有一次状态变更成功。
9. 截止后仍未提交的负责人显示逾期，已提交待审核者不记为护士逾期。
10. 发布人按年月日时分选择截止时间；过去时间被服务端拒绝。
11. 发布任务时上传图片、PDF 和 Word 附件；接收人可下载，非接收人无权下载，上传及发布有审计记录。
12. 管理列表默认不显示勾选框；先选批量关闭或批量取消操作，再显示勾选框。混合状态时只处理符合状态机的项目，返回成功、跳过和失败数量，每个成功项目均保留历史及审计记录。
13. 无 `task.manage` 权限人员批量关闭应被服务端拒绝；无 `task.publish` 权限人员取消草稿应被拒绝。
14. 列表发起时间取服务端发布时间，草稿显示未发布；已完成只含简单任务完成和审核通过，未完成含待完成、已提交待审核及退回补充，两者之和等于有效负责人总数。被排除负责人不计入。
15. 已发布任务的剩余时间每秒更新，截止后显示逾期时长；关闭、撤回、取消任务不继续倒计时。详情看板与人员明细统计一致，筛选已完成、未完成结果正确。

## 5. 跨端一致性验收

- 小程序确认后，H5 刷新可看到相同确认状态和服务端时间。
- H5 提交任务后，小程序和管理端显示相同提交版本。
- 小程序与 H5 使用同一工号和密码登录并关联同一个内部用户。
- 微信身份关联失败时仍可使用账号密码登录小程序。
- 多个并发请求遇到访问令牌过期时只刷新一次；H5 和小程序不因令牌轮换竞争退出登录。
- 角色、状态、等级、错误和审计操作面向用户显示中文；服务器内部枚举仍保持稳定。
- 管理列表的任务普通/重要/紧急、草稿/已发布/已关闭/已撤回/已取消及账号四种状态均用不同颜色和中文文字共同标识。
- 平台专属功能失败不改变核心业务状态。

## 6. 数据与审计验收

- 首页汇总数量可以逐项追溯到明细。
- 导出数据与当前筛选和服务端统计一致。
- 发布、版本修改、确认、提交、审核、催办、导出和账号管理均有审计日志。
- 审计日志包含操作人、操作时间、目标对象、动作和结果。
- 普通业务接口不能修改或删除审计日志。
- 数据库备份能够在独立测试环境恢复并通过核心数据核对。

## 7. 完成门槛

所有 P0 需求、身份与权限用例、通知闭环、任务闭环和跨端一致性用例通过后，V1.0 才具备本科室试运行条件。微信订阅消息发送失败可以作为已知外部渠道问题记录，但站内待办、业务状态和人工催办必须正常工作。
