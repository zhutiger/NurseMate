# 护知音 HZY V1.0 需求清单

> 状态：开发基线  
> 更新日期：2026年11月18日

## 1. 版本目标

V1.0 必须证明两条业务闭环可以可靠运行：

1. 护士长发布通知后，可以准确看到每名接收人的查看、确认和逾期情况。
2. 护士长发布任务后，可以准确看到每名负责人的提交、审核、退回、重提和完成情况。

## 2. 用户与身份

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| AUTH-01 | 管理员预建护士账号 | 未预建人员不能自行注册为科室成员 |
| AUTH-02 | 使用一次性激活码激活账号 | 激活码单次使用、过期失效并记录操作 |
| AUTH-03 | 小程序和 H5 使用同一工号与密码登录 | 两个端登录后关联同一内部用户 ID |
| AUTH-04 | 小程序关联微信身份 | 登录不依赖微信身份，关联信息用于订阅消息等微信能力 |
| AUTH-05 | 支持安全退出与会话失效 | 退出、停用和重置后旧会话失效 |
| AUTH-06 | 管理员重置绑定或 H5 密码 | 必须填写原因并生成审计记录 |
| AUTH-07 | 停用离科人员 | 停用后禁止登录，历史记录保留 |
| AUTH-08 | 已停用账号重新启用 | 由护士长填写原因转为待激活，重新发放一次性激活码，旧会话保持失效 |

## 3. 人员与权限

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| USER-01 | 新增、编辑和查询人员 | 支持姓名、工号、角色、分组和在岗状态 |
| USER-02 | 批量导入人员 | 返回成功、失败及失败原因，不产生重复工号 |
| USER-03 | 管理护理分组 | 人员可属于一个主要分组，历史业务不随分组变化 |
| USER-04 | 设置护士长、协管员和护士 | 同一科室至少保留一名有效护士长 |
| USER-05 | 为协管员单独授权 | 发布、统计、催办、审核、导出权限可独立配置 |
| USER-06 | 按角色和状态限制数据范围 | 普通护士不能访问管理数据或他人记录 |
| USER-07 | 编辑人员账号、角色和协管员权限 | 工号保持唯一，权限变更由护士长执行并审计 |
| USER-08 | 查看停用记录并按账号状态筛选 | 列表展示停用原因和服务端停用时间，支持四种账号状态筛选 |

## 4. 通知闭环

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| NOTICE-01 | 创建和保存通知草稿 | 草稿仅创建人和有管理权限人员可见 |
| NOTICE-02 | 配置标题、正文、等级、附件和期限 | 必填项、长度、文件类型和截止时间得到校验 |
| NOTICE-03 | 按全员、分组或指定人员选择接收人 | 发布前显示去重后的实际接收人数 |
| NOTICE-04 | 发布前预览并二次确认 | 明确显示等级、期限和接收人数 |
| NOTICE-05 | 发布时固定接收名单 | 后续人员或分组变化不改变历史接收名单 |
| NOTICE-06 | 记录首次查看 | 打开详情后由服务端记录首次查看时间 |
| NOTICE-07 | 主动阅读确认 | 一名接收人对同一版本只能成功确认一次 |
| NOTICE-08 | 查询确认统计和人员明细 | 汇总数量与人员明细保持一致 |
| NOTICE-09 | 支持通知版本 | 重要内容修改产生新版本并保留旧版本 |
| NOTICE-10 | 支持撤回和关闭 | 不物理删除，必须记录原因和操作人 |
| NOTICE-11 | 支持接收人追加和排除 | 变更保留历史并重新计算有效统计口径 |
| NOTICE-12 | 管理列表按状态和等级筛选 | 五种业务状态与普通、重要、紧急三级均可查询 |

## 5. 任务闭环

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| TASK-01 | 创建简单完成或审核完成任务 | 发布前明确完成方式且发布后不可直接切换 |
| TASK-02 | 指定全员、分组或个人负责人 | 发布后为每名负责人生成独立任务记录 |
| TASK-03 | 完成简单任务 | 服务端记录完成时间，重复请求不产生重复记录 |
| TASK-04 | 提交文字反馈和附件 | 每次提交形成不可覆盖的提交版本 |
| TASK-05 | 审核通过 | 仅有审核权限人员可操作并记录审核时间 |
| TASK-06 | 退回补充 | 退回必须填写意见，负责人可以重新提交 |
| TASK-07 | 查询执行进度和人员明细 | 区分待完成、已提交、退回、已通过和逾期 |
| TASK-08 | 关闭和撤回任务 | 保留已产生的执行和审核历史 |
| TASK-10 | 发布任务附加图片和文档 | 支持图片、PDF、Word 文件，负责人可按权限下载，文件留痕且不覆盖历史 |
| TASK-11 | 选择精确完成截止时间 | 发布人可选择年月日时分，服务端拒绝已过期时间 |
| TASK-12 | 在管理列表批量关闭或取消任务 | 仅已发布任务可关闭、仅草稿可取消；逐项留痕并展示成功、跳过和失败数量 |

## 6. 提醒与催办

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| REMIND-01 | 首页生成个人待办 | 只展示本人有效且尚未完成的事项 |
| REMIND-02 | 支持截止前和逾期提醒计划 | 提醒任务可重试且不会重复创建业务状态 |
| REMIND-03 | 支持微信订阅消息辅助提醒 | 发送结果与阅读确认状态相互独立 |
| REMIND-04 | 支持单人和批量人工催办 | 记录操作人、对象、渠道、时间和结果 |
| REMIND-05 | 限制提醒频率 | 同一对象和事项遵循间隔及次数上限 |

## 7. 查询、导出与审计

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| REPORT-01 | 查询护士个人历史记录 | 只显示本人记录并支持类型、状态和时间筛选 |
| REPORT-02 | 查看管理首页概览 | 待确认、待完成、待审核和逾期数量可追溯到明细 |
| REPORT-03 | 导出通知确认明细 | 导出权限受控并记录审计日志 |
| REPORT-04 | 导出任务处理明细 | 包含提交、审核、退回和完成时间 |
| AUDIT-01 | 记录关键业务操作 | 操作人、时间、对象、动作和结果完整 |
| AUDIT-02 | 审计记录不可由普通业务接口修改 | 管理查询不提供编辑和删除能力 |

## 8. 跨端要求

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| CLIENT-01 | 核心护士流程支持微信小程序和 H5 | 两端使用同一账号体系，业务数据与状态一致 |
| CLIENT-02 | 平台能力通过适配层提供 | 页面不直接散布微信专属调用 |
| CLIENT-03 | 主要页面适配常用手机宽度 | 无横向滚动，主要按钮可触达 |
| CLIENT-04 | 管理员高频操作支持移动端 | 发布、统计、催办和审核可在小程序完成 |
| CLIENT-05 | 所有面向用户的标签、状态和错误提示使用中文 | 工号、角色、通知和任务状态以及网络错误均不直接显示内部英文代码 |
| CLIENT-08 | 管理列表用颜色辅助区分等级与状态 | 任务三级重要程度、五种任务状态和四种账号状态各有可辨颜色，并同时保留中文文字 |

## 9. 非功能要求

| 编号 | 要求 |
| --- | --- |
| NFR-01 | 主要列表和详情接口 95% 请求在正常网络下 2 秒内返回 |
| NFR-02 | 发布、确认、提交和审核接口具备幂等控制 |
| NFR-03 | 多步骤写入使用数据库事务保证一致性 |
| NFR-04 | 所有接口校验登录、角色、权限和数据范围 |
| NFR-05 | 生产环境全链路 HTTPS，密钥不进入代码仓库 |
| NFR-06 | 数据库可备份并在上线前完成至少一次恢复演练 |
| NFR-07 | 关键任务失败可告警，日志不记录密码、令牌和完整敏感凭据 |
| NFR-08 | 并发请求共享一次令牌刷新，页面加载失败可重试 | 不因刷新令牌轮换竞争清除有效会话，失败时保留已加载数据并显示中文提示 |

## 10. V1.0 排除项

- 多科室、多院区和院级组织树。
- 排班表编辑、自动排班和考勤打卡。
- 培训考试、题库、积分、绩效和个人速度排名。
- AI 自动评价、内容生成和违规判定。
- 患者数据、病历、诊疗图片和身份证信息。
- 群聊、即时通讯和音视频通话。
- 自定义工作流设计器和微服务架构。
