# ADR-001：V1.0 技术栈与部署形态

- 状态：已接受
- 日期：2026-11-19
- 适用版本：V1.0

## 背景

呼吸通需要同时支持微信小程序和 H5，团队规模为单科室 10～30 人。业务重点是可靠状态流转、权限、提醒和审计，不需要微服务复杂度。开发过程不使用本地运行环境验证，统一部署到云端测试服务器联调。

## 决策

- 客户端使用 uni-app、Vue 3、TypeScript 和 Pinia，共享小程序与 H5 核心页面。
- 微信专属能力放在 `apps/client` 平台适配层，业务页面不直接调用微信 API。
- 服务端使用 NestJS 和 TypeScript，按业务模块组织单体应用。
- PostgreSQL 保存业务事实和不可覆盖历史，Prisma 管理模型与迁移。
- Redis 和 BullMQ 处理提醒任务、异步导出及必要短期状态，不作为业务事实来源。
- 采用 pnpm workspace monorepo；跨应用类型、枚举和校验规则放入 `packages`。
- 测试环境采用 Linux、Docker Compose 和 Nginx，应用部署目录为 `/apps/NurseMate`。
- 应用密钥和服务器凭据由环境变量或密钥管理服务提供，不进入 Git。

## 理由

- TypeScript 贯穿前后端，降低接口模型重复和跨端协作成本。
- uni-app 能覆盖当前要求的微信小程序与 H5，且保留平台差异隔离能力。
- NestJS 的模块、守卫、验证和依赖注入适合权限与审计要求明确的业务系统。
- PostgreSQL 的事务、约束和索引适合通知确认、任务提交及并发审核场景。
- 单体模块化部署与当前用户量匹配，运维和故障定位成本更低。

## 影响

- 发布前必须同时验证小程序和 H5 的核心护士流程。
- 服务端是权限和状态判断的最终依据。
- 所有数据库结构变化必须生成 Prisma migration，并在云端测试库验证。
- 如果未来扩展为院级多科室系统，应另建 ADR 评估组织隔离、容量和部署拆分，不在 V1.0 预埋复杂微服务。
